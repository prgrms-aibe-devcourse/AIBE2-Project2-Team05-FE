# 충돌 해결 우선순위 및 결정 기준

## 개요
프로젝트 병합 시 발생하는 파일 충돌에 대한 구체적인 해결 기준과 우선순위를 정의합니다.

## 충돌 해결 기본 원칙

### 1. 기능 완전성 우선
- 더 완전하게 구현된 기능을 우선 채택
- 템플릿 수준 vs 완전 구현 → 완전 구현 선택
- 정적 UI vs 동적 기능 → 동적 기능 선택

### 2. 디자인 시스템 일관성 유지
- styled-components 기반 스타일 우선
- #3682F8 메인 색상 유지
- Pretendard 폰트 시스템 유지
- CSS 파일은 styled-components로 변환

### 3. 고유 가치 기능 보존
- AI 추천 기능 (현재 프로젝트)
- 장소 관련 기능 (현재 프로젝트)
- 관리 시스템 (팀원 프로젝트)
- 차트 기능 (팀원 프로젝트)

## 충돌 발생 시 단계별 해결 프로세스

### 1단계: 백업 확인
```bash
# 백업 상태 확인
git tag --list | grep pre-merge
git branch --list | grep backup
```

### 2단계: 충돌 분석
1. 충돌 파일 식별
2. 각 버전의 기능 비교
3. 위 기준표에 따른 우선순위 확인

### 3단계: 해결 방법 선택
- **완전 교체**: `git checkout source_branch -- file_path`
- **수동 병합**: 충돌 마커를 보고 직접 편집
- **부분 채택**: 특정 기능만 복사

### 4단계: 스타일 변환
- CSS → styled-components 변환
- 색상 통일 (#3682F8)
- 폰트 시스템 적용 (Pretendard)

### 5단계: 기능 테스트
- 기본 기능 동작 확인
- 스타일 일관성 확인
- 오류 로그 점검

## 예외 상황 처리

### 1. 양쪽 모두 고유한 가치가 있는 경우
- **원칙**: 기능 통합 시도
- **방법**: 컴포넌트 분리 후 조건부 렌더링
- **예시**: 여러 종류의 차트 컴포넌트

### 2. 스타일 충돌이 심한 경우
- **원칙**: styled-components 우선
- **방법**: 점진적 변환
- **임시**: 주석 처리 후 나중에 처리

### 3. 의존성 충돌
- **버전 충돌**: 더 높은 버전 선택
- **호환성 문제**: package-lock.json 재생성
- **신규 의존성**: 필요성 검토 후 추가

## 긴급 상황 대응

### 복원이 필요한 경우
```bash
# 전체 복원
git reset --hard v1.0.0-pre-merge-current

# 특정 파일만 복원
git checkout v1.0.0-pre-merge-current -- src/components/AIRecommendationSection.tsx
```

### 병합 중단이 필요한 경우
```bash
# 진행 중인 병합 중단
git merge --abort

# 백업 브랜치로 전환
git checkout backup/pre-merge-state
```
